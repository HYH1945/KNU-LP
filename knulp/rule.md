# 브랜치, 커밋 등 잡다한 규칙

어느정도 통일성도 고려하고 

AI 에이전트 사용하실거도 감안해서 필요할까 싶어 작성해두었습니다

## 브랜치 규칙
1. `develop`에서 개인 브랜치를 생성 : 예시 : AI/Task_1/yolo, BE/login
2. 작업 완료 후 `develop`으로 Pull Request 생성 및 merge
3. 검증후 최종 결과물을 `develop` → `main`으로 merge

---

## 커밋 메세지 규칙 (커밋컨벤션)

## 형식

```
type(scope): 설명
```

**예시:** `feat(FE): 로그인 페이지 추가`

## Type

| Type | 설명 |
|------|------|
| `feat` | 새로운 기능 |
| `fix` | 버그 수정 |
| `docs` | 문서 수정 |
| `refactor` | 리팩토링 (기능 변화 없) |
| `chore` | 기타 작업 |
| `rename` | 파일 혹은 폴더명 수정
| `remove` | 파일 삭제

## Scope

| Scope | 설명 |
|-------|------|
| `FE` | 프론트엔드 |
| `BE` | 백엔드 |
| `AI/Task_1` | 과업 1 |
| `AI/Task_2` | 과업 2 |
| `AI/Task_3` | 과업 3 |
| `*` | 여러 모듈에 걸친 변경 |

**예시:** `feat(AI/Task_1): 데이터 전처리 스크립트 추가`

---

## 코드 작성 규칙

- 변수명, 함수명은 영어로 작성
- 주석은 한글 허용
- 각 모듈 디렉토리 안에서만 작업 (다른 모듈 직접 수정 금지)
- 새 파일 생성 시 해당 모듈의 구조 규칙을 따를 것
